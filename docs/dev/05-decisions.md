# 决策记录（ADR）

> 记录**架构性与方向性的选择**，包含被否决的方案与理由。
> 目的：避免换机器/换 AI 工具后重复讨论已经定过的事。

## 记录格式

```markdown
### ADR-NNN — <决策标题>

- **日期**：YYYY-MM-DD
- **状态**：已采纳 / 已废弃 / 被 ADR-XXX 取代
- **背景**：为什么要做这个决定
- **决策**：选了什么
- **理由**：为什么选它
- **被否决的方案**：考虑过但没选的，以及原因
- **影响**：这个决定的后果
```

### ADR-001 — 以上游 v1.7.17 纯净快照作为基线

- **日期**：2026-09-17
- **状态**：已采纳
- **背景**：二开需要长期跟进上游更新，同时要能清楚区分"上游代码"与"我们的改动"
- **决策**：把未改动的上游快照作为仓库第一个提交 `3df1aff`，所有改动叠加在其之上；配置 `upstream` remote
- **理由**：保留完整上游历史锚点，可与上游做三方合并；`git diff 3df1aff..HEAD` 能精确列出我们的改动
- **被否决的方案**：直接 fork 上游仓库（会带入完整历史，仓库体积大且克隆慢；且上游历史对二开无实际价值）
- **影响**：不得 rebase / amend / 丢弃 `3df1aff`；上游更新用 `git merge upstream/main` 而非重新导入

### ADR-004 — Windows 的 python3 用 venv 内解释器副本解决

- **日期**：2026-09-17
- **状态**：已采纳
- **背景**：`tools/*.yaml` 中 16 个配方以 `python3` 为命令；Windows 的 `python3` 指向微软商店应用执行别名，未安装商店版 Python 时不可用
- **决策**：在 `venv\Scripts\` 内复制 `python.exe` 为 `python3.exe`，并由启动器把该目录前置进 PATH
- **理由**：venv 内解释器按所在目录解析 `pyvenv.cfg`，副本仍属 venv 环境，能用到全部依赖；不污染系统目录，可随 venv 一起删除
- **被否决的方案**：
  - 在系统 Python 目录放 `python3.cmd`（`.cmd` 经 cmd.exe 转发会破坏含 `%`、`&`、`<>` 的内联 Python 脚本）
  - 修改系统 PATH 或在 WindowsApps 目录做手脚（侵入系统，且涉及系统设置）
- **影响**：所有工具执行必须通过 `run-windows.cmd` 启动（或自行确保 `venv\Scripts` 在 PATH 中）

### ADR-005 — `web/static/vendor/` 强制纳入版本控制

- **日期**：2026-09-17
- **状态**：已采纳
- **背景**：上游 `.gitignore` 的 `vendor/` 规则（Go 约定）同时匹配了前端目录 `web/static/vendor/`，导致 xterm / marked / cytoscape 等运行时依赖不会被提交
- **决策**：用 `git add -f web/static/vendor` 强制纳入，并在 `AGENTS.md` 中标注为"已知坑"
- **理由**：前端无构建步骤，这些库直接由 `index.html` 引用，缺失会导致页面功能异常；保证 clone 后开箱可用
- **被否决的方案**：修改 `.gitignore` 规则（会偏离上游文件，增加后续合并冲突）
- **影响**：该目录内容不要删除、不要"顺手修复"忽略规则；上游合并时若冲突保留双方

### ADR-006 — 换行符统一为 LF（`core.autocrlf=input`）

- **日期**：2026-09-17
- **状态**：已采纳
- **背景**：开发在 Windows，可能迁移到 Linux；Windows 默认 `autocrlf=true` 会在检出时转 CRLF，破坏 `*.sh` 的解释器行
- **决策**：仓库设 `core.autocrlf=input`，以 LF 提交
- **理由**：跨平台一致；避免 `run.sh` 之类脚本在 Linux 上出现 `^M` 报错
- **影响**：新机器克隆后若 git 报告大量改动，先检查本机 `core.autocrlf` 设置

### ADR-007 — Windows 使用 `run-windows.cmd` 而非上游 `run.sh`

- **日期**：2026-09-17
- **状态**：已采纳
- **背景**：上游 `run.sh` 是 bash 脚本，且在执行环境检查时（早于 venv 激活）就要求 `python3` 可用，在 Windows 上必然失败
- **决策**：新增 `run-windows.cmd`，负责 PATH 修复（`venv\Scripts` + Git `usr\bin`）后启动二进制
- **理由**：不改上游文件即可支持 Windows；PATH 修复同时解决 `python3` 与 `sh`（`tools/exec.yaml`）的解析问题
- **被否决的方案**：修改 `run.sh` 使其兼容 Windows（偏离上游文件，增加合并负担）
- **影响**：Windows 上一律用 `run-windows.cmd`；Linux/macOS 继续用 `run.sh`

### ADR-008 — 文档以 `AGENTS.md` 为单一事实源，各 IDE 只放薄入口

- **日期**：2026-09-17
- **状态**：已采纳
- **背景**：用户需要迁移到其它机器与其它 AI IDE 后无缝衔接，若为每个工具各写一份文档会产生多处重复、难以同步
- **决策**：`AGENTS.md` 作为唯一事实源；`.trae/rules/`、`.cursor/rules/`、`CLAUDE.md` 只写"指针"指向它；细节拆到 `docs/dev/*`
- **理由**：避免文档漂移；任何 IDE 只要读到入口就能找到完整上下文
- **影响**：新增约定只改 `AGENTS.md` 或 `docs/dev/*`；入口文件仅在 IDE 有特殊机制要求时才调整

### ADR-009 — 项目定位由"渗透测试"转为"浏览器驱动的安全运营 Agent"

- **日期**：2026-09-18
- **状态**：已采纳（部分取代 ADR-002 中对目标形态的描述）
- **背景**：二开方向定为承接 `D:\project\python\态势感知告警处理` 的能力——用 Agent 替代"人工抓包 → 手工写接口层 → 界面逐条处置"的低效链路
- **决策**：FlowSage 定位为浏览器驱动的安全运营 Agent，核心能力为 **浏览器托管 / 会话接管 / 流量观测 / Selenium 级页面操控 / 接口理解 / 任务执行**
- **理由**：上游已有 Agent、MCP、RBAC、持久化等基础设施可直接复用；站点登录必须过图形验证码，必须借助真实浏览器
- **被否决的方案**：只做"流量抓取工具"（无法闭环解决处置痛点）、只做"接口代码生成"（价值单薄）
- **影响**：上游的 C2 / WebShell / 后渗透等渗透能力在后续阶段评估裁剪；`docs/dev/06-design.md` 为需求与架构的单一来源

### ADR-010 — Go 主导，Python 规则引擎复用而非重写

- **日期**：2026-09-18
- **状态**：已采纳
- **背景**：`alertctl/smart.py` 的处置话术经 5832 条历史台账回放验证（73% 可提交、26% 需补全、无遗漏），口径由用户逐类确认
- **决策**：浏览器、流量、页面操控、接口理解、任务编排全部用 Go 实现；**处置规则引擎保留在 Python，通过稳定契约复用**
- **理由**：已验证的业务逻辑重写风险高、收益低；重写还需连带重写 66 项断言的验证脚本
- **被否决的方案**：全部用 Go 重写（口径漂移风险 + 验证成本）、全部改用 Python（浪费上游 Go 侧 Agent/MCP 能力）
- **影响**：发布物需携带 Python 运行时（可复用 alertctl 现有的便携打包方案）；Go 与 Python 之间不得有编译期耦合

### ADR-011 — 浏览器驱动选 chromedp，浏览器来源系统 Edge 优先

- **日期**：2026-09-18
- **状态**：已采纳
- **背景**：需要全量捕获请求/响应（含载荷），且要满足"什么环境都能跑"
- **决策**：用 **chromedp** 驱动；浏览器按 `系统 Chrome → 系统 Edge → 随包便携 Chromium` 顺序探测
- **理由**：chromedp 对原始 CDP 最直接，能订阅 Network 域事件做抓包，无需中间人证书或改系统代理；Windows 10+ 自带 Edge（本机实测 Edge 153 可用），便携 Chromium 仅作离线老机器的兜底
- **被否决的方案**：Playwright（需额外下载浏览器、体积大）、纯 HTTP 代理抓包（要装证书、改系统代理，现场不可行）
- **影响**：`internal/browser` 需实现浏览器探测与降级逻辑；企业策略若禁用 CDP 需实测并准备降级方案

### ADR-012 — Go 与 Python 之间用稳定 JSON 契约隔离

- **日期**：2026-09-18
- **状态**：已采纳
- **背景**：规则引擎要从 Go 侧调用，需要确定集成方式与数据边界
- **决策**：Python 侧只加薄壳，**不改 `smart.py` 逻辑**；契约为 —— 输入归一化告警 JSON（等价 `Alert` 模型 + reasons 字典），输出 `HandlePlan` JSON（`status / reason_name / message / note / submittable`）
- **理由**：契约与现有 `alertctl/models.py::HandlePlan` 完全一致，Python 侧改动量趋近于零，既有 66 项断言继续有效
- **被否决的方案**：把规则逻辑移植为 Go（见 ADR-010）、让 LLM 直接生成话术（口径不可控）
- **影响**：优先用子进程方式接入（无网络依赖、易调试）；若日后改为 MCP 接入，契约不变

### ADR-013 — 话术生成"规则优先 + LLM 兜底"

- **日期**：2026-09-18
- **状态**：已采纳
- **背景**：既有八类告警的话术已固定，但站点必然出现新的告警类型
- **决策**：已验证类型一律走确定性规则模板；**仅对未知类型**由 LLM 提议话术，经人工确认后固化为新规则
- **理由**：保证已确认口径不漂移，同时避免新类型完全阻塞作业
- **被否决的方案**：全部沿用现有规则（新类型无法处理）、全部交 LLM（口径漂移、无法通过历史台账回归）
- **影响**：新增告警类型时需同步更新 `verify_mock.py` 的期望用例；LLM 产出必须标记为"待确认"，不得直接提交

### ADR-014 — 产品形态确定为 Web 端，操作不经命令行

- **日期**：2026-09-18
- **状态**：已采纳（部分取代 ADR-009 的能力清单）
- **背景**：用户明确要求"不要用终端命令操作，类似原项目的方式在 Web 端操作"
- **决策**：全部功能以 Web 控制台为交互面；`cmd/flowsage` CLI 降级为**开发与排障用的内部工具**，不作为产品交互面
- **理由**：目标用户是现场值守/运维人员，Web 界面门槛最低；上游控制台基础设施可复用
- **被否决的方案**：CLI 优先（MVP-1 的做法），对非开发用户不友好
- **影响**：能力要经 HTTP 暴露并配 Web 页面；`internal/browser` 等引擎代码保留复用，不因形态调整而废弃

### ADR-015 — 产品定位：把 Web 应用转换成 Python 程序

- **日期**：2026-09-18
- **状态**：已采纳
- **背景**：用户明确三个功能点，共同指向"产出 Python 程序"这一目标
- **决策**：定位为「Web 应用 → Python 程序」的转换工具
  - F1 流量 → Python CLI/TUI 客户端
  - F2 浏览器操作 → Python Selenium 式自动化脚本
  - F3 API 分析 → 找出全部接口（F1/F2 的地基）
- **理由**：三个功能共享同一套接口理解与代码生成管线；alertctl 是该产出物的手工样板，证明路径可行
- **影响**：`alertctl` 的定位由"复用的规则引擎"改为"**产出物工程规范的样板**"（取代 ADR-010/012 中关于复用 smart.py 的结论）；
  渗透测试相关能力（C2、WebShell、后渗透）整体剥离

### ADR-016 — 四种流量通道并存，HAR 导入优先实现

- **日期**：2026-09-18
- **状态**：已采纳
- **背景**：不同现场条件差异大：有的能装扩展，有的只能离线，有的浏览器受策略限制
- **决策**：四种通道全做，实现优先级为 **HAR 导入 → 浏览器扩展 → 托管浏览器 → CDP 连接**；
  全部产出**同一份归一化流量记录**，分析引擎只认这一种格式
- **理由**：HAR 导入最简单可靠、可离线、可复现，且已有真实样本（`192.169.20.251.har`）可开发验证；
  浏览器扩展复用用户自己的浏览器，天然解决登录与验证码
- **被否决的方案**：只做托管浏览器（受企业策略影响、需在托管窗口重新登录）、只做代理抓包（要装证书、改系统代理，现场不可行）
- **影响**：需要一层归一化抽象；通道之间不得各自实现分析逻辑

### ADR-018 — 控制台精简为专用控制台

- **状态**：已采纳
- **背景**：上游控制台有 20+ 个页面（漏洞管理、WebShell、C2、批量任务等），绝大多数与新定位无关
